# Практические работы по утилитам Unix

Реализация на C11 трёх практических работ. Каждая папка содержит исходники, Makefile и пояснения к своей работе; её можно собирать отдельно.

| --- | --- | --- |
| Практическая работа 1 | `mycat`, `mygrep` | [practice_1_cat_grep](practice_1_cat_grep) |
| Практическая работа 2 | `myls` | [practice_2_ls](practice_2_ls) |
| Практическая работа 3 | `mychmod` | [practice_3_chmod](practice_3_chmod) |

## Сборка

Нужны `make` и компилятор C, например GCC или Clang. Из корня репозитория:

```sh
make
```

Либо отдельно, например:

```sh
cd practice_1_cat_grep
make
printf 'first\n\nsecond\n' > file.txt
./mycat -nE file.txt
./mycat file.txt | ./mygrep first
```

Для остальных работ:

```sh
cd practice_2_ls
make
./myls -la .
```

```sh
cd practice_3_chmod
make
printf 'example\n' > file.txt
./mychmod 766 file.txt
ls -l file.txt
```

Каждый блок запускается из корня репозитория. Для удаления исполняемых файлов выполните `make clean` в нужной папке или в корне для всех работ.

## Проверки

Из корня, с установленным Python 3:

```sh
make test
```

14 групп сравнительных тестов проверяют вывод, опции, конвейеры, права, ошибки и цвета в терминале. Данные создаются во временных каталогах. GitHub Actions автоматически собирает программы и запускает проверки на Ubuntu Linux при загрузке изменений.

Ориентир — GNU/Linux, включая Astra Linux; исходники также собираются на macOS. Исполняемые файлы в репозиторий не включены: их нужно собирать на целевой системе.

## Границы совместимости

Реализованы опции из заданий и дополнительные возможности, перечисленные в README каждой работы. Все расширения GNU coreutils не воспроизводятся. `mygrep` рассчитан на текст без NUL и один шаблон без переводов строк. `myls` не воспроизводит маркеры ACL и расширенных атрибутов, экранирование необычных имён GNU ls и все варианты терминальных отступов. На macOS системные утилиты BSD отличаются некоторыми деталями вывода и поведения.
